# Starter Template: New Feature or Change

Use when: asking a model to add or change code in an existing project.

```
Add [feature or change] to [project / component].

Context: [language, framework, runtime, relevant versions].
Existing conventions: [link to or describe a similar file or pattern to follow].
Requirements: [the behavior you want, including edge cases].
Constraints: [what not to change, e.g. public API, unrelated files, dependencies].
Done when: [observable behavior and which tests should pass].

Make the smallest change that satisfies this. State any assumptions you made about versions or dependencies, and don't claim tests passed unless you ran them.
```

How to use: the "Done when" line is the one most people skip - it is what lets the model check its own work.
