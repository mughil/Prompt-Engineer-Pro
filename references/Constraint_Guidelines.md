# Constraint Guidelines

Add constraints only when they guide a real decision. Common categories include audience, tone, length, scope, format, sources, time horizon, tools, privacy, and safety/appropriateness bounds.

Distinguish hard requirements from preferences. Avoid excessive “must” statements, overlapping prohibitions, or contradictory rules. Use measurable constraints where meaningful, but do not force arbitrary word counts or exact formats on tasks that do not need them.

A safety/appropriateness constraint can define boundaries for an otherwise allowed task. It is not the same as the hard refusal boundary in Prompt_Safety_Guidelines.md; see that guide before optimizing requests near a safety boundary.
