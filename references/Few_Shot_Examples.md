# Few-Shot Examples

Use examples when a model may struggle to infer a desired format, tone, transformation, or edge-case decision from rules alone.

A good example is representative, short, and aligned with the requested output. Include contrasting examples when the boundary matters. Explain what the example demonstrates if it is not self-evident. Avoid examples that contain accidental facts or requirements the user did not intend to generalize.

Do not add examples for trivial tasks. A prompt can say “follow this format” and include one sample output. For sensitive data, use fictional or sanitized examples. Check that examples do not contradict the instructions or each other.
